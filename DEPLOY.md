# DRISHTI — Production Deploy Guide

Three services, three platforms:

| Service              | Host    | URL pattern                          |
| -------------------- | ------- | ------------------------------------ |
| Frontend (React)     | Vercel  | `https://drishti-xyz.vercel.app`     |
| Backend (Spring Boot)| Render  | `https://drishti-backend.onrender.com` |
| AI assistant (Python)| Render  | `https://drishti-ai.onrender.com`    |
| Database             | NeonDB  | (already cloud)                      |

All free tier. Render free services sleep after 15 min idle (~30s cold start on the next request).

---

## 1 — Push the latest code to GitHub

You're on branch `demo_branch` of `abhijith-abn/DRISHTI`. From the repo root:

```bash
git status
git add -A
git commit -m "Prep for deploy: Dockerfile, render.yaml, vercel.json"
git push origin demo_branch
```

## 2 — Deploy the backend + AI service to Render

Both services are defined in [`render.yaml`](./render.yaml) (a Render Blueprint).

1. Sign in at <https://dashboard.render.com> with GitHub.
2. **New** → **Blueprint** → pick your `DRISHTI` repo → branch `demo_branch` → Render will detect `render.yaml` and propose two services.
3. Click **Apply**.
4. Wait until both services say **Live** (first build ~5 min for Java, ~2 min for Python).
5. For each service, open it → **Environment** tab and fill in the secrets marked `sync: false`:

### Backend (`drishti-backend`)

| Variable           | Value                                                                   |
| ------------------ | ----------------------------------------------------------------------- |
| `DB_URL`           | `jdbc:postgresql://YOUR-NEON-HOST/neondb?sslmode=require&channelBinding=require` |
| `DB_USERNAME`      | `neondb_owner`                                                          |
| `DB_PASSWORD`      | (from Neon)                                                             |
| `JWT_SECRET`       | auto-generated by Render — leave it                                     |
| `APP_CORS_ORIGINS` | (you'll fill this in **step 3** after Vercel)                           |
| `FRONTEND_URL`     | (same as `APP_CORS_ORIGINS`)                                            |
| `GOOGLE_CLIENT_ID` | your OAuth Web client ID                                                |
| `CHAT_API_URL`     | `https://drishti-ai.onrender.com/api/chat` (use your actual AI URL)     |
| `MAIL_USERNAME`    | (leave blank or set real SMTP)                                          |
| `MAIL_PASSWORD`    | (leave blank or set real SMTP)                                          |

Optional but recommended for prod logs:
- `LOG_LEVEL_SECURITY=INFO`
- `LOG_LEVEL_OAUTH2=INFO`
- `LOG_LEVEL_APP=INFO`

### AI service (`drishti-ai`)

| Variable          | Value                              |
| ----------------- | ---------------------------------- |
| `NVIDIA_API_KEY`  | (your build.nvidia.com key)        |
| `AI_MODEL`        | `meta/llama-3.3-70b-instruct` (default) |

Click **Save, rebuild** on each service. Confirm health:

```bash
curl https://drishti-backend.onrender.com/api/public/health
curl https://drishti-ai.onrender.com/
```

Both should return JSON.

## 3 — Deploy the frontend to Vercel

1. Sign in at <https://vercel.com> with GitHub.
2. **Add New → Project** → pick your `DRISHTI` repo.
3. **Root Directory** → `drishti-frontend` (click *Edit* to set this — important).
4. **Framework Preset** → Create React App (auto-detected).
5. Before clicking Deploy, open **Environment Variables** and add:

| Name                          | Value                                          |
| ----------------------------- | ---------------------------------------------- |
| `REACT_APP_API_URL`           | `https://drishti-backend.onrender.com`         |
| `REACT_APP_AI_URL`            | `https://drishti-ai.onrender.com`              |
| `REACT_APP_GOOGLE_CLIENT_ID`  | your OAuth Web client ID (same as backend)     |

6. Click **Deploy**. Wait ~2 min.
7. Vercel gives you a URL like `https://drishti-xyz.vercel.app`.

---

## 4 — Wire frontend ↔ backend CORS

1. Back to the Render `drishti-backend` service → **Environment** tab → set:
   - `APP_CORS_ORIGINS` = `https://drishti-xyz.vercel.app` (your real Vercel URL)
   - `FRONTEND_URL`     = `https://drishti-xyz.vercel.app`
2. Render auto-redeploys.

---

## 5 — Update Google OAuth

1. <https://console.cloud.google.com> → APIs & Services → Credentials → click your OAuth client.
2. **Authorized JavaScript origins** → Add → `https://drishti-xyz.vercel.app`.
3. Save. The change is near-instant.

## 6 — One-time DB setup

If you previously used Supabase, drop the old `profiles` table once so Hibernate can rebuild the new schema:

```sql
DROP TABLE IF EXISTS profiles CASCADE;
```

Run that from the Neon SQL editor before the backend's first deploy completes (or right after, and restart the backend from Render).

After the backend boots, it auto-seeds the dev admin (`drishtidev@gmail.com` / `drishti123`).

## 7 — Smoke test

1. Open the Vercel URL. The home page loads with the login form on the right.
2. **Cookie banner** appears at the bottom — accept any choice.
3. Try **Sign in with Google** → pick a Google account → you should land on `/course` (or get the phone verification modal first).
4. Visit `/admin-login`, sign in as `drishtidev@gmail.com` / `drishti123` → land on `/admin`.
5. Manage Courses → create a course with a YouTube URL → switch to Preview Mode → confirm video plays on `/course/:id`.
6. Bottom-right ✨ → ask the AI assistant a commerce question.

## Keeping the demo warm

Render's free tier sleeps after 15 min idle. Before your live demo:
- Hit the backend once: `curl https://drishti-backend.onrender.com/api/public/health`
- Hit the AI: `curl https://drishti-ai.onrender.com/`
- Or just open the Vercel URL — it'll wake both within ~30s.

For zero cold-start during a demo, upgrade just `drishti-backend` to **$7/mo** ("Starter" plan, always-on). Or use a free service like UptimeRobot/Cron-job.org to ping `/api/public/health` every 14 minutes.

## Common pitfalls

- **CORS error in browser console** → `APP_CORS_ORIGINS` doesn't exactly match your Vercel URL. No trailing slash, include `https://`.
- **Google button missing in prod** → `REACT_APP_GOOGLE_CLIENT_ID` was unset *at Vercel build time*. Set it then redeploy.
- **"Failed to fetch" on login** → backend is sleeping. Wait ~30s and retry. Or check Render dashboard logs.
- **Mixed-content blocked** → some env var still has `http://` instead of `https://`. Re-check all URLs.
- **"password authentication failed" in backend logs** → DB password mismatch. Reset in Neon, paste into Render env.
